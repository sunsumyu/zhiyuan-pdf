# Postmortem 2026-10-05 — 静止态部分模糊 + 接缝（"settle 必然清晰"违约：旧档瓦片滞留）

## 现象（用户截图，154% 静止态）

视口内存在一条水平接缝（"核心优势"标题附近）：接缝以上五行文字是低档位
位图被拉伸的模糊；以下是原生分辨率清晰渲染；接缝处有一行被切半的文字
残片（两层的映射差了几个像素，同一行在两层各露一半）。

**定性：违反 P2 契约后半句"settle 必然清晰"**（HANDOFF #1 预留的
"若未来用户报 settle 后仍模糊，那才是新缺陷"触发）。非手势、非已接受的
P2 模糊。

## 取证（`zoom_rest_blur_probe.spec.ts`，2026-10-05）

复现序列：缩放至 1.682%（模拟用户 130→243→154 的多档带手势）→ **收敛尾
中途滚动 +400px** → 静置 → 结构快照。实测：

| 层 | 实测 | 判读 |
|---|---|---|
| zoom 状态 | lastR = target = visual = 1.6818 | 缩放状态自认已渲染完成（排除 H3 主因） |
| base canvas | 整页位图 @ **1.634**，拉伸 2.9% | = ADR-0016 像素预算 clamp（budget_zoom=1.634），**设计内**——视口应由原生层覆盖 |
| detail patch | 原生档、覆盖视口 ✓，但 **z-index 2** | 在瓦片层**之下**，救不了模糊区 |
| **tile layer (z=3)** | **12 块瓦片横跨 5 个档位：1.47 / 1.516 / 1.59 / 1.65 / 1.682** | **1.47 档瓦片 present scale = 1.682/1.47 = 1.144 → 14.4% 拉伸 = 用户看到的强模糊** |
| heal 测试 | 缩放微推后档位仍混（1.59 残留） | 粘滞，不会自愈 |
| 滚动活性 | 尾中滚动 → 700ms 内 21 次渲染；+1px 滚动 → 0 次 | H1（滚动抑制）本次未参与；小滚动不刷新属设计 |

层叠顺序（代码实证）：main canvas z=1 < detail patch z=2 < **tile layer
z=3（最上层）**——静止态用户看到的就是瓦片网格。

## 根因

**瓦片网格的清场规则只看"最后画的瓦片"的档位，对每块瓦片的个体陈旧度
失明。** 链条：

1. 手势期瓦片按绘制时刻的档位上屏（`drawTile` 接受落后 intent ≤1 档的
   请求；一旦入 `active` 就留在 DOM）；
2. `clearDom` 条件 = `|target − presentedZoom| > STEP + ε && settled`，
   其中 `presentedZoom` = 最后一块绘制的瓦片档位——visual 冲到 1.682 后
   该值恒"新鲜"，**旧档瓦片永远不会触发清场**；
3. settle 时 `use_viewport_tile=true`（1.682 > budget 1.634），渲染走
   视口补丁而非网格重排——没有任何环节重画旧档瓦片；
4. 静止态 tile tick 休眠（zoomGap ≤ EPS 不再 scheduleTick）→ 网格以
   多档混合状态**无限期滞留**。

用户画面的每个细节都对上：强模糊 = 1.47 档 14.4% 拉伸；接缝 = 新旧档
瓦片边界；切半残行 = 边界两侧 present scale 不同导致的亚行错位；"上半糊
下半清" = 上半是手势早期档位瓦片、下半是后期新档瓦片。

## 关联

与问题 #1（手势中双影 + 右缘灰带，用户视频）同族：都是**瓦片网格的
per-tile 档位陈旧**在手势中（双影 = 旧档瓦片与新内容错位）和静止后
（本条 = 旧档瓦片滞留）的表现。修复应一并覆盖。

## 修复方向（未实施，待立项）

1. **清场规则按瓦片个体档位判**：`|target − tile.renderZoom| > STEP + ε`
   的瓦片在 settle 后重排/重渲，而非只看 presentedZoom；
2. 或 settle 后对 `active` 网格做一次"陈旧瓦片补渲"（沿用现有泵）；
3. 契约：settle 后 N 秒采样瓦片档位集合，`max(renderZoom) − min(renderZoom)`
   ≤ STEP（现违约：0.212），加像素无关的"视口内不容许 present scale
   偏离 1 超 X%"断言。

## 修复记录（2026-10-05，方向 1 落地）

`tile_layer.ts`：settle 态清场分支增加 **per-tile 陈旧扫除**
（`gridHasStaleTiles(target)`：任一可见瓦片档位距 target > 1 量化步即
清扫），并在清扫时 **`tileFacade.clearPage(page)` + `clear()`** ——实现中
发现一个隐藏死锁：只清 DOM 不清 Rust 侧，TileManager 仍把被扫键记为
ready，重调度时队列判定已就绪不再入队，泵空转，网格永远空白（新契约
`zoom_tile_band_uniformity` 以 populated=0 抓住）。`clearPage` 把 Rust
缓存状态一并失效，重排才真正入队重渲。

验证（`zoom_tile_band_uniformity.spec.ts`，多档带手势 + 收敛尾中滚动 +
settle 后 6 采样）：

| 状态 | worstDev | 网格 |
|---|---|---|
| 修复前（红灯） | **0.6818**（含页面打开 1.0 档瓦片，比截图的 1.47 更极端） | 10 块跨 2 档 |
| 修复中（只清 DOM） | — | **0 块（死锁）**——契约 populated 守卫抓住 |
| 修复后 | **0.0000**，3 轮稳定 | 6 块单一档位 1.6818 |

门禁：tsc 0、vitest 163/163（wasm 重建）、zoom 全套件 **23/23**（含新契约）。
非空转守卫（手势跨 ≥2 档 + 网格 ≥2 瓦片）防 fixture 空转。清扫只在
settle 态触发（手势行为不动，ADR-0009 的 1 档容差保留）。
